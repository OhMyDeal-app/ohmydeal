# OhMyDeal Beta 0.8 — безопасное тестирование на отдельном Supabase

Этот пакет заменяет прежнюю тестовую сборку в GitHub-ветке `beta-08-test`.
Он **не использует** рабочий Supabase. Сборка Netlify остановится с понятной ошибкой, если настройки тестового проекта отсутствуют или вместо него указана рабочая база.

## До загрузки ZIP в GitHub
1. Создать НОВЫЙ проект Supabase, например `ohmydeal-beta08-test`.
2. В SQL Editor нового проекта отдельно выполнить `SETUP_BETA_05.sql`, `SETUP_BETA_07.sql`, `SETUP_BETA_08.sql` (в таком порядке). Их нельзя запускать на рабочем проекте ради теста.
3. В Supabase > Project Settings > Data API (или API Keys) скопировать **Project URL** и **publishable key** (не `service_role`, не `secret`).
4. В Netlify открыть проект `ohmydeal-beta08-test` > Project configuration > Environment variables, создать:
   * `VITE_SUPABASE_URL` = URL НОВОГО тестового Supabase.
   * `VITE_SUPABASE_PUBLISHABLE_KEY` = publishable key НОВОГО тестового Supabase.
   Scope: All scopes или Builds.
5. После этого загрузить содержимое ZIP в GitHub-ветку `beta-08-test` и нажать Commit. Netlify автоматически пересоберёт.

## Первое тестирование
- Открыть тестовый Netlify URL в приватной вкладке.
- Создать отдельные тестовые аккаунты, не использовать свои рабочие пароли и не вводить реальных клиентов.
- Проверить регистрацию, вход, личный профиль и доступ к вкладке «Партнёры» до верификации.
- Проверку публикации проводить после ручной серверной верификации тестового аккаунта (не через публичный интерфейс).

## Ограничения
- Добавление в личный список подборки есть, но нет клиентской ссылки и PDF.
- Чужие фотографии не показываются; защищённые превью и водяные знаки ещё не реализованы.
- Реальные фото/клиентские данные не используем.
- Успешный статус Netlify `Published` подтверждает сборку, а не безопасность или функциональность базы.
